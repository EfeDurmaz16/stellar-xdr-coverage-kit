\kicker{TECHNICAL ARCHITECTURE}
\titleline{Stellar XDR Coverage Kit}
When a wallet upgrades its Stellar SDK, can it still read the same ledger and recover every affected account? The kit checks both the decoded XDR and the rows the wallet stores.

\sectionline{Two checks on the same corpus}
\diagram{replay.pdf}{0.98}
{\small\sffamily\color{mid}Proposed replay paths. Standalone XDR values enter the SDK path. Complete ledger records can also enter wallet-backend through a local RPC endpoint.}\par

\sectionline{An independent reference for each result}
The manifest gives every case a stable ID, source, XDR type, expected values and provenance. It records CAP and protocol attribution when known. Historical captures also carry a network, ledger sequence, protocol and digest. Synthetic examples claim no observed ledger or network.

A pinned Rust generator will rebuild cases for the public and test network passphrases where relevant. Full-ledger cases will be checked against stellar-core's \texttt{-{}-check-lcm} goldens. Expected values for standalone types come from their underlying fields. Unsigned 64-bit IDs are compared as decimal strings.

\kicker{IMPLEMENTATION AND RELEASE}
\titleline{How a run earns a pass}
\sectionline{SDK and indexer reports}
Each SDK runner will emit a row for each applicable fixture. Field equality and byte equality are separate checks. The matrix will show missing results, version pins and exceptions. Initial coverage includes issuer order, account and offer IDs, muxed accounts, vector limits, nested authorization entries and map key identity.

The reference adapter will feed ordered \texttt{LedgerCloseMeta} records to a pinned wallet-backend over local \texttt{getLedgers}. The verifier will compare persisted effects, participants and row counts with changes recorded in ledger meta. The report distinguishes a wrong value from a missing row and identifies the first affected ledger.

\sectionline{Hardening and operating limits}
{\small
\begin{tabularx}{\linewidth}{@{}p{31mm}@{\hspace{4mm}}>{\raggedright\arraybackslash}X@{}}
\toprule
\labeltext{Risk} & \labeltext{Control and visible signal}\\
\midrule
Misread input & Three Go lint rules flag trust in fields core passes through, missing depth or size caps, and envelope-based attribution. Findings include a rule ID and source line.\\[3pt]
Incomplete runs & CI checks expected ledger ranges, row counts and results. A partial run fails. Streaming, a memory ceiling and a timeout bound the replay. The report records the last ledger and peak memory.\\[3pt]
Stale fixtures & Scheduled read-only checks compare public network progress with the last tested protocol and range. Ordinary pull-request tests use local fixtures after setup. No signing keys, funds or user telemetry are needed.\\
\bottomrule
\end{tabularx}}\par\vspace{4pt}

\sectionline{Release and first protocol upgrade}
\diagram{upgrade.pdf}{0.96}
The MIT release will include a reviewer command, the coverage matrix, a mainnet-history replay report and a field guide covering validated fields, caps, ledger participants, muxed accounts and SEP-0023 signed payloads. A core or platform engineer will be asked to review the guide.

I will maintain the kit through the first protocol upgrade after release, rerun both paths and publish the result. Confirmed compatibility findings will link to upstream reports. Sensitive findings will follow the affected project's disclosure process.
